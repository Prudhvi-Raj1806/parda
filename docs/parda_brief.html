Parda: an offline privacy firewall for clinical records

Yugaantar 2026 · DevForge, Track 3 (Secret Wards) · Team: Prudhvi Raj (lead), Prahlad, Sanskar · Repository: github.com/Prudhvi-Raj1806/parda

1. Mission and USP

Parda turns a messy folder of hospital exports into a research release that a voter-list attacker cannot easily use. It runs offline on the standard library and PyYAML, uses no model, and writes a report that counts only what it actually published. What is different: (1) names and addresses are learned from the dataset itself and removed in every channel, including file names, keys, headers, metadata and base64; (2) patients are linked only on evidence that identifies one person, and contradictions block a merge even when a single pair looks good; (3) a release gate re-checks every file's bytes before publication, so unverified output is never written.

3. Detection in three scripts

  • Structured fields. Column and key names are matched against English and romanised or Devanagari Hindi aliases (Naam, Pita/Pati ka Naam, Janm Tithi, Pata, Umar). A value that reads as an address is treated as one in unnamed columns.
  • Free text. Labelled names (Name:, नाम:), relatives (S/o, D/o, W/o, C/O with a name), honorifics (ji, sahab, chachu) and candidates next to a phone or contact cue. Doctors (Dr., with qualifications) and medicine names are never names.
  • Identifier shapes. Aadhaar (plain and masked), ABHA, PAN, e-mail, hospital numbers (UHID, SNJ, JJH, DHH, IPD, ADM), insurance IDs, and 10-digit mobiles written in Latin or Devanagari digits.

4. Linking and pseudonyms

Records are compared only inside shared blocks (an identifier, a phone, a name). Evidence weights: trusted global ID 100, namespaced hospital number 85, mobile 45, date of birth 35, strong name 35, moderate name 20, relative 20, locality 10, age 5. A pair links at 85 or more with independent corroboration. Two different Aadhaar or hospital numbers, incompatible dates of birth, or a record naming two people always reject a pair. A cluster merges only if every member pair is consistent. Pseudonyms are PSN- plus six characters of HMAC-SHA256 over the cluster's smallest identifier, keyed with RAKSHA_SECRET. Plain hashes are not used: they can be reversed against a voter list.

6. Security design

  • The secret is read from RAKSHA_SECRET, never printed, logged or stored. The run refuses to start without it. Keys are derived per purpose (pseudonyms, dates), so one key never serves two jobs.
  • stdout and errors show counts, exception classes and input hashes only. No temporary files; the registry and profiles live in memory until the gate passes.
  • Each file is verified before writing; unverified output is never published, and the input is re-hashed.
  • Quarantine is withholding, not copying: unreadable, binary, malformed or unsafe files appear in the report with a reason.

7. Known limitations (honest)

  • Names without a cue (a bare first name in a nursing note) are missed. Devanagari names are found after a label or next to a phone. The held-out sets contain such cases, and the scores above already include them.
  • Linking recall on the practice data is 0.83. Records with no identifier, such as lab rows that carry only initials, stay unlinked (null). That protects precision, and the held-out recall figures count only records that carry an identifier.
  • Column rules depend on headers; unfamiliar headers fall back to value checks and leak more (1.2% versus 0.6%).
  • Re-identification risk remains. 12 of 46 classes stay below k=5 even after widening and district suppression, and 12.5% of practice patients are still identified by our simplified attacker. The kit's own attacker has not been run, and the held-out sets do not exercise the k-anonymity step.
  • Held-out sets were written by us. Both sets use conventions we chose, so they are only a rough check on unseen data. The hidden datasets may differ in ways neither set covers.
  • Known gaps: names with no label, honorific or nearby phone; initials in unusual positions; dates in formats we have not seen; wards kept as clinical context.
  • Not verified: the kit's submission checker on Windows, an offline clean-machine run, peak memory, and full FHIR R4 validation.
